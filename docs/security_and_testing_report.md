# تقرير المراجعة الأمنية والهندسية وحالات الاختبار
**المشروع:** نظام إدارة مينيو المطعم الذكي (QR & NFC)
**التاريخ:** 03-08-2026
**المنصة:** تطبيق ويب (React + Vite + TypeScript)

## 1. ملخص تنفيذي
تم إجراء فحص شامل للكود المصدري للتطبيق، وهو تطبيق يعتمد بشكل كبير على جانب العميل (Client-Side) مع تخزين محلي (LocalStorage) وتوجيه لطلبات الواتساب. تم التركيز على أمان المدخلات والمخرجات، وإدارة الحالة، وقابلية التوسع. تم العثور على ثغرات متوسطة ومنخفضة الخطورة تتعلق بمعالجة البيانات المخزنة والتوجيه، وتم إصلاحها بنجاح دون التأثير على وظائف النظام.

## 2. قائمة المخاطر (Risk Assessment)

| الخطر / الثغرة | مستوى الخطورة | الوصف | الإجراء المتخذ |
| :--- | :---: | :--- | :--- |
| **XSS (عبر `locationUrl`)** | **متوسط** | إمكانية إدخال روابط خبيثة تبدأ بـ `javascript:` ضمن حقل رابط الموقع (GPS)، والتي قد يتم تنفيذها إذا نقر المستخدم على "معاينة". | تم تقييد الرابط ليبدأ بـ `http` فقط، وفي حال عدم تطابقه يتم التوجيه إلى `#`. |
| **تعطل التطبيق (JSON Parsing)** | **منخفض** | فشل في تحويل نصوص `localStorage` عند تلف البيانات أو العبث بها، مما يؤدي إلى تعطل الصفحة (White Screen of Death). | تم إضافة كتلة `try...catch` لكل عملية `JSON.parse` مع إرجاع القيم الافتراضية في حالة الفشل. |
| **تخزين بيانات غير مشفرة** | **منخفض** | الاعتماد على `localStorage` لحفظ التكوينات وسلة التسوق، مما يسمح لأي سكريبت محلي (أو مستخدم على نفس الجهاز) برؤيتها أو تعديلها. | تم توثيقه كـ "مخاطر مقبولة" (Accepted Risk) لأن البيانات غير حساسة حالياً، مع توصية بالتشفير مستقبلاً. |

## 3. الإصلاحات بالكود (Code Fixes)

### 3.1 معالجة استثناءات التخزين المحلي (`src/hooks/useMenuState.ts`)
**السبب:** تحسين متانة التطبيق (Robustness) ضد بيانات المتصفح التالفة.
```typescript
// قبل:
const saved = localStorage.getItem('smart_menu_config');
return saved ? JSON.parse(saved) : initialRestaurantConfig;

// بعد:
const saved = localStorage.getItem('smart_menu_config');
try {
  return saved ? JSON.parse(saved) : initialRestaurantConfig;
} catch (e) {
  console.error("Error parsing smart_menu_config from localStorage:", e);
  return initialRestaurantConfig; // الرجوع للوضع الآمن
}
```

### 3.2 منع ثغرات XSS في الروابط (`src/components/CartDrawer.tsx`)
**السبب:** تطهير المخرجات (Output Sanitization) لمنع تنفيذ أكواد جافاسكريبت.
```tsx
// قبل:
<a href={customer.locationUrl} target="_blank" rel="noopener noreferrer">

// بعد:
<a href={customer.locationUrl?.startsWith('http') ? customer.locationUrl : '#'} target="_blank" rel="noopener noreferrer">
```

## 4. قائمة حالات الاختبار (Test Cases & Threat Modeling)

### 4.1 اختبارات وحدوية (Unit Tests)
* **`formatWhatsAppMessage`:**
  * **مدخلات متوقعة:** سلة تحتوي على منتج واحد + خدمة "داخل المطعم" -> التحقق من وجود رقم الطاولة والمجموع الفرعي الصحيح.
  * **مدخلات غير متوقعة (Edge Cases):** سلة فارغة، كميات سالبة أو صفرية -> يجب ألا يتم احتسابها أو إرجاع رسالة خطأ.
* **`useMenuState`:**
  * **حالة:** إدخال قيمة نصية غير صالحة لـ JSON في `localStorage` -> التحقق من أن الهوك يعود بالقيم الافتراضية بدلاً من رمي استثناء وتوقف التطبيق.

### 4.2 اختبارات تكاملية (Integration Tests)
* **تدفق الإضافة للسلة (Add to Cart Flow):**
  1. النقر على منتج لإضافته.
  2. التحقق من تحديث العداد (Badge) في الأسفل.
  3. فتح السلة والتحقق من حساب السعر الإجمالي بدقة.
* **تحديث اللغة (i18n):**
  * التبديل بين العربية والإنجليزية وملاحظة تغيير اتجاه النص (RTL إلى LTR) وتحديث النصوص دون فقدان حالة السلة.

### 4.3 سيناريوهات هجومية (Threat Modeling)
* **سيناريو 1 (Manipulation of Pricing):**
  * **الهجوم:** محاولة تعديل السعر في `localStorage` (`smart_menu_cart`).
  * **النتيجة الحالية:** سيتم عرض السعر المعدل في واجهة المستخدم وإرساله عبر الواتساب.
  * **التخفيف (Mitigation):** لا يوجد تأثير أمني خطير لأن التنفيذ النهائي يتم عبر المطعم نفسه (من خلال قراءة رسالة الواتساب ومطابقتها بالأسعار الحقيقية)، ومع ذلك يوصى بمراجعة الطلبات بدقة.
* **سيناريو 2 (Reflected/Stored XSS):**
  * **الهجوم:** إدخال أكواد `<script>alert(1)</script>` في حقل ملاحظات العميل.
  * **النتيجة الحالية:** إطار عمل React يقوم تلقائياً بتشفير (Escape) هذه المدخلات عند عرضها في الـ DOM، لذلك التطبيق آمن. وتم تأمين الروابط المباشرة أيضاً كما ذُكر أعلاه لمنع `javascript:` URIs.

## 5. توصيات لتحسين البنية والأمن (Recommendations)

1. **التحقق من صحة المدخلات (Input Validation):** استخدام مكتبات مثل `Zod` للتحقق من صحة نماذج الإدخال (أرقام الهواتف، العناوين) قبل قبولها.
2. **إدارة الحالة المعقدة:** مع نمو التطبيق، قد يكون من الأفضل الانتقال من `localStorage` إلى حل متكامل مثل `IndexedDB` أو الاعتماد على مكتبات إدارة الحالة (مثل Zustand) مع آلية تشفير (Encryption) للملفات المحلية الحساسة.
3. **التواصل مع الواتساب:** حالياً يتم بناء الرابط في جهة العميل (Client-Side). لتجنب العبث بالأسعار وتزييف الطلبات، يفضل مستقبلاً إنشاء واجهة خلفية (Backend Server) تقوم بحساب الأسعار النهائية، التحقق منها، ثم توجيه العميل أو إرسال الطلب بشكل موثق.
4. **تدقيق الحزم (Dependency Auditing):** تفعيل أوامر `npm audit` بانتظام لضمان عدم وجود حزم تحتوي على ثغرات معروفة، وتحديثها دورياً لتطبيق مبادئ الدفاع الطبقي (Defense in Depth).
